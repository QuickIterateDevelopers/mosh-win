EXPERIMENTAL · v0.1

エージェント時代に、
切れにくいリモートシェルを。

TCPの接続は、ネットワークが変わった瞬間に終わります。mosh はそこを UDP と状態同期で解決しました。

⇄

ネットワークが変わると終わる

Wi-Fiからテザリングへ、会社から自宅へ。IPアドレスが変わればSSHは切断され、作業中のシェルもエディタも一からやり直し。

…

遅い回線で打鍵がもたつく

SSHは打った文字がサーバーから返ってくるまで表示されません。遅延の大きい回線では、1文字ごとに待たされます。

⊞

Windowsにはmoshがなかった

本家 mosh はUnix向け。WindowsではWSLやCygwinを経由するしかなく、Windows Terminal からそのまま使えるクライアントがありませんでした。

いつものターミナルで、
いつものコマンド。

接続が途切れても画面はそのまま。戻ってきた瞬間に、最新の状態へ追いつきます。

[mosh] ubuntu@server: ~ —☐✕
mosh: Last contact 14 seconds ago. [To quit: Ctrl-^ .]
PS C:\Users\me> mosh-win ubuntu@server
ubuntu@server:~$ tail -f /var/log/app.log
2026-10-25 14:02:11 INFO  job #4182 started
2026-10-25 14:02:13 INFO  job #4182 finished (1.92s)
── ここで Wi-Fi からテザリングへ切り替え ──
2026-10-25 14:02:29 INFO  job #4183 started
2026-10-25 14:02:30 INFO  job #4183 finished (0.88s)

回線が途切れている間は上部にバーを表示。つながり直すと自動で消えます。

本家 mosh を、
そのまま Windows へ。

mosh 1.4 のクライアントを Rust に移植。サーバー側は標準の mosh-server のままで動きます。

01

ローミング

クライアントのIPアドレスが変わっても、サーバーは新しいアドレスへ自動で追従。スリープからの復帰後もセッションが続きます。

02

予測ローカルエコー

遅い回線では、打った文字をサーバーの返事を待たずに表示。予測が外れたら自動で取り消します。速いLANでは控えめに。

03

本家と同じプロトコル

AES-128-OCB による暗号化、UDPでの状態同期、画面差分の生成まで本家の規則どおり。mosh-server 1.3 / 1.4 と互換です。

04

単体exe、約720KB

ランタイムもDLLも不要。mosh-win.exe ひとつをPATHの通った場所に置けば使えます。

05

Windows Terminal ネイティブ

Windows コンソールの VT 入出力を直接扱います。日本語の入出力、ウィンドウのリサイズ、タイトル表示にも対応。

06

いつもの ssh をそのまま

サーバーの起動には Windows 標準の OpenSSH を使用。~/.ssh/config も鍵エージェントも、普段の設定がそのまま効きます。

使い方は、ssh とほぼ同じ。

ホスト名を渡すだけ。ssh でサーバーを起動し、あとは UDP でつなぎ直します。

# ssh と同じ書き方で接続
PS> mosh-win ubuntu@server.example.com

# ログイン後に実行するコマンドを指定
PS> mosh-win server -- tmux attach

# 終了は Ctrl-^ を押してから . （シェルで exit してもOK）
# 別の ssh 設定ファイルを使う
PS> mosh-win --ssh="ssh -F C:\path\to\config" server

# 毎回指定しない場合は環境変数で
PS> $env:MOSH_WIN_SSH = "ssh -F C:\path\to\config"
PS> mosh-win server
# 予測エコーを常に表示 / 表示しない（既定は回線に応じて自動）
PS> mosh-win -a server
PS> mosh-win -n server

# サーバー側の UDP ポートを指定（ファイアウォールに合わせて）
PS> mosh-win -p 60001 server

# すべてのオプション
PS> mosh-win --help

よくある質問

サーバー側には何が必要？

本家の mosh-server がインストールされていること（Ubuntu / Debian なら sudo apt install mosh）と、ssh でログインできることです。加えて、サーバーの UDP 60000〜61000 番（-p で指定した場合はそのポート）に届く必要があります。

本家 mosh と何が違うの？

本家 mosh 1.4 のクライアント部分を Rust で書き直し、Windows のコンソールで直接動くようにしたものです。プロトコルは同じなので、サーバー側は本家のまま使えます。サーバー（mosh-server）は含まれていません。

どのくらい完成しているの？

現在は実験的なバージョン（v0.1）です。Linux 上の mosh-server 1.4.0 を相手に、シェル、vim、top、日本語の入出力、リサイズなどは確認済みです。ネットワーク切り替え時のローミングと、IME での日本語入力は実環境での検証がまだ十分ではありません。不具合は GitHub の Issues へお知らせください。

速い回線だと予測エコーが出ないのはなぜ？

本家と同じく、既定では回線が遅いと判断したときだけ予測表示を行います。常に表示したい場合は -a、使わない場合は -n を付けてください。

動作環境は？

Windows 10 / 11（64bit）。Windows Terminal、PowerShell、コマンドプロンプトで動作します。サーバーの起動に Windows 標準の OpenSSH クライアント（ssh）を使います。
